# VPN-ноды

Один Compose-проект `xray` запускает Xray и gRPC-прокси node в сети хоста.
Базовый `xray.json` находится **в образе** `xray-latest`; входы, пользователи
и маршруты добавляются control через Xray API после запуска. Конфиг больше
не копируется на сервер. Образ основан на `ghcr.io/xtls/xray-core:26.9.9`.

Одноразовый сервис `cert-init` в Compose создаёт обычную самоподписанную пару
`tls.crt`/`tls.key` в постоянном Docker volume `xray_tls-certs`. Xray ждёт
успешного завершения `cert-init`. Закрытый ключ не попадает в образ или Git. Файлы в
`/etc/xray` от прежнего развёртывания не используются и не удаляются. При
первом переходе будет **новый сертификат** (старые клиенты Hysteria2 с
закреплённым отпечатком потребовали бы обновления, если бы они были).

Теги в приватном Docker Hub: `xray-latest`, `xray-certs-latest` и `node-latest`.
`task xray-publish` публикует два первых. На машине сборки
нужны Docker Buildx и вход с правом Write; на нодах — токен с правом Read в
локальном `.env.node` (`DOCKERHUB_TOKEN=...`, `chmod 600 .env.node`).

```sh
task xray-publish
task node-publish
task node-init
```

`node-init` нужен для первого перехода: он скачает образы и поднимет сервисы;
Compose сам создаст сертификат в volume. Перед первым запуском на новом сервере
нужно остановить старый host-`node.service`, если он ещё слушает `:9093`.
Существующий Xray перезапустится при переходе на новый образ; control
восстановит динамические настройки при очередной синхронизации.

Для обновлений запускайте `task xray-deploy` или `task node-deploy` после
публикации соответствующего образа. Обе команды обновляют только свой сервис,
если образ изменился. Общий `task deploy` вызывает их последовательно и
параллельно с обновлением control. Перезапуск Xray кратковременно сбрасывает
его динамические входы до синхронизации control. Сертификат в volume сохраняется.
